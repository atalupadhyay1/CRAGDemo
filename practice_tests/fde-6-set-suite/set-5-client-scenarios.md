## 1. Discovery and customer context

### 1.

A sponsor requests an “AI-powered operations portal.” What is the best discovery question to start with?

A. Can the sponsor approve a public data export?  
B. Which user decision or workflow is costly today, and how is success measured?  
C. How soon can the team add every requested feature?  
D. Which model has the most parameters?  

### 2.

Executives describe a process differently from frontline operators. What should the FDE do?

A. Treat all differences as irrelevant.  
B. Observe the workflow and validate both perspectives with concrete examples and artifacts.  
C. Choose the executive's version without checking operations.  
D. Ask developers to invent a third process.  

### 3.

A customer describes a painful manual report but cannot provide its source data. What is a useful next step?

A. Replace the workflow with a model immediately.  
B. Map the report's decisions and dependencies, then request an approved sample or sandbox path.  
C. Copy data from an employee's personal email.  
D. Promise an exact replica before seeing the data.  

### 4.

The customer says an issue happens “all the time.” What should you ask?

A. Start rewriting the system before documenting symptoms.  
B. Assume every user sees identical behavior.  
C. Request recent examples, frequency, affected users, impact, and conditions where it does not happen.  
D. Accept the phrase as a quantified requirement.  

### 5.

A stakeholder names a requested feature but not who will use it. What is important to learn?

A. How to avoid involving users.  
B. User roles, workflow context, decision authority, and current workarounds.  
C. Whether the feature can have a longer title.  
D. The stakeholder's favorite programming language only.  

### 6.

A customer has an informal workaround that is absent from process documents. What should happen?

A. Automate only the written happy path and claim full coverage.  
B. Observe and document the real workflow, including exceptions, before replacing it.  
C. Treat undocumented practice as impossible.  
D. Tell users to stop the workaround immediately.  

### 7.

A sponsor wants “faster decisions.” How do you make that outcome testable?

A. Assume any faster answer is correct.  
B. Define a baseline decision time, target, population, quality guardrail, and measurement window.  
C. Measure only login count.  
D. Replace the phrase with “modern AI.”  

### 8.

A user's workflow crosses several teams. Who should be involved in discovery?

A. No one until the project is complete.  
B. Representative users and owners at key handoffs, plus the accountable workflow sponsor.  
C. Only the software team building the interface.  
D. Only the highest-ranking executive.  

### 9.

A customer asks for data fields that appear sensitive. What is the right discovery step?

A. Assume customer-provided data has no restrictions.  
B. Clarify purpose, classification, authorization, minimum necessary fields, and approved handling.  
C. Put the values into a shared prompt.  
D. Collect all fields first and decide privacy later.  

### 10.

A pilot's user group is not representative of the wider operation. What is the concern?

A. Pilot results may not generalize; include diverse workflows and define limits on conclusions.  
B. A small group guarantees unbiased outcomes.  
C. Only executives should participate.  
D. The pilot is automatically invalid and must be abandoned.

D. A guarantee of perfection with no measurement.

A. A final architecture with no customer review.

D. A hard-coded implementation assumption.

D. Bypass the policy quietly to preserve the relationship.

B. Value, urgency, effort, dependencies, risk, and what existing commitment would move.  
C. How to keep the change undocumented.  
D. Whether it can be added without changing anything.  

### 23.

A. A commitment to ship every easy idea.

D. The fact that the code is already open in an editor.  

### 24.

A. Surface the risk, test a safe fallback or narrower scope, and obtain an explicit decision from the owner.  
B. Skip authorization to remove the dependency.  
C. Claim the feature is complete using mock output.  
D. Hide the dependency until launch.  

### 25.

The team has room for one more task. Which should normally come first?

A. A high-impact blocker or risk reduction tied to the agreed outcome.  
B. A cosmetic improvement unrelated to the workflow.  
C. A refactor with no known quality or maintenance benefit.  
D. A speculative feature with no user evidence.  

### 26.

A customer asks for a date before technical discovery is complete. What should you communicate?

A. An exact date with no caveats.  
B. A range/assumptions, key unknowns, next validation step, and when the estimate can be refined.  
C. A date chosen to end the discussion.  
D. No estimate and no plan to learn more.  

### 27.

The customer has asked for a bespoke feature for one account. What should be evaluated?

A. Whether to duplicate the whole product.  
B. Customer value, reusable capability, maintenance/upgrade cost, and whether configuration can meet the need.  
C. Whether bespoke code can be hidden from future maintainers.  
D. Whether to avoid documenting it.  

### 28.

A stakeholder adds an urgent request that displaces a lower-priority one. What should be recorded?

A. The decision, rationale, owner, impact on scope/date, and revised acceptance criteria.  
B. The change in a private message no one can find.  
C. Only the new code diff.  
D. Nothing if the deadline remains unchanged.  

### 29.

The customer insists the solution must be perfect before any user feedback. What is a constructive response?

A. Remove the users from validation.  
B. Wait indefinitely for perfection.  
C. Release to everyone without controls.  
D. Propose a safe staged pilot with defined users, scope, rollback, and learning objectives.  

### 30.

The first approach is not working, but significant effort is invested. What should the team do?

A. Add complexity to defend the original decision.  
B. Hide the results from the customer.  
C. Reassess evidence, sunk cost, alternatives, and agreed outcomes; pivot if another path is better.  
D. Continue only because time has already been spent.

### 39.
